# KubeSentinel

Runtime threat detection and automatic containment for Kubernetes. It watches kernel events with eBPF,
scores each pod against its own learned behaviour, explains what looks wrong, and quarantines the pod.

![ci](https://github.com/Amir-Abdaoui/kubesentinel/actions/workflows/ci.yml/badge.svg)

## How it works

    pod syscalls -> Falco (eBPF) -> falcosidekick -> /falco (token auth) -> sliding windows
      -> Isolation Forest + z-score guard + rules -> ATT&CK / CWE + explanation
      -> responder: label pod -> Calico deny-all NetworkPolicy -> SHA-256 evidence snapshot

## Quick start without a cluster

    python3 -m venv .venv && .venv/bin/pip install -r requirements.txt
    PYTHONPATH=src .venv/bin/python -m pytest -q tests
    PYTHONPATH=src .venv/bin/python -m kubesentinel evaluate

## Quick start on a real cluster (Linux or WSL2)

    make cluster calico build deploy falco
    ./attacks/run_all.sh && ./scripts/alerts.sh
    python scripts/benchmark.py run --reps 10 --benign-min 30

## Results

Real-cluster results are in `docs/BENCHMARK.md`, generated by `scripts/benchmark.py`.
`docs/RESULTS.md` is synthetic and only validates the pipeline.

## Known limitations

Thin baseline for quiet workloads, signature-based attack labelling, any `kubectl exec` counts as a shell,
single-node Falco in a lab cluster, evidence stored in an emptyDir.

## Layout

`src/kubesentinel` detector, responder and API; `k8s` manifests; `falco` rules; `attacks` harmless
simulations; `scripts` benchmark and tools; `site` public demo site (Vercel); `docs` documentation.

## Security and ethics

Lab use only. The vulnerable workload and attack scripts must never run on a cluster you do not own.
The public site replays recorded data and never connects to a cluster.
